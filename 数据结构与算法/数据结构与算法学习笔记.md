### 动态规划算法

动态规划算法一般用于解决**最值问题**。动态规划其实是运筹学的一种最优化方法，只不过在计算机问题上应用比较多，比如“求最长递增子序列”、“最小编辑距离”等。

求解动态规划问题的核心在于**穷举**，因为要求最值，肯定*要把所有可行的答案穷举出来，然后在其中找最值*。

然而动态规划问题并不是简单的穷举问题，因为这类问题**存在重叠子问题**。如果只是简单地暴力穷举，效率会十分低下，所以需要**使用一些辅助存储空间用作“备忘录”或“DP table（动态规划表）”去记录各个子问题的解**，从而优化穷举过程，避免不必要的计算。

而且**动态规划问题一定具备最优子结构**，即可以通过子问题的解得到原问题的解（最值）。

虽然动态规划的核心思想就是穷举最值，但是因为求解问题的具体内容不同，穷举所有可行解并不是一件简单的事，只有列出**正确的“状态转移方程”或动态规划函数**才能正确的穷举。

综上，**动态规划具有三要素：1. 重叠子问题；2. 最优子结构；3. 状态转移方程**。

在动态规划算法设计中最难的往往是——列出动态转移方程。可以按如下的步骤思考状态转移方程：

1. 明确状态
2. 定义DP table或动态规划函数的含义
3. 明确状态转移的选择
4. 明确初始状态

**总结**：将待求问题分解为若干个相互重叠的子问题，每个子问题对应决策过程的一个阶段。一般来说，子问题的重叠关系表现在给定问题求解的递推关系（动态规划函数）中，将子问题的解求解一次并填（记录）DP table中，当需要再次求解此子问题时，可以通过查DP table获得，避免大量重复的计算。

#### 理解重叠子问题

以斐波那契数列为例（斐波那契数列严格来说不是动态规划问题，这里只是作为理解”什么是重叠子问题“的例子）。

```
f(n) = 1 (n=1,2)
f(n) = f(n-1)+f(n-2) (n>2)
```

当我们通过递归的方式去求解`f(n)`时：

```java
int f(int n){
	if(n == 1 || n == 2)
		return 1;
	return f(n-1)+f(n-2);
}
```

虽然代码看上去十分简洁，但是算法的效率很低，因为当我们画出函数调用的递归树时会发现对于下层的`f(1)、f(2)、f(3)、依此类推`，会多次调用，重复计算。

以`f(5)`具体说明:

```
f(5) = f(4)+f(3)
	f(4) = f(3)+f(2)
		f(3) = f(2)+f(1)
			f(2) = 1
			f(1) = 1
	f(3) = f(2)+f(1)
		f(2) = 1
		f(1) =1
```

可以发现在解答过程中，存在大量的重复计算（在递归树中，很多节点的值是重复的）。

通过斐波那契数列，可以理解**重叠子问题**——某个子问题（阶段）的求解依赖之前子问题（阶段）的求解结果。就像把很多书摞在桌子上，当我们要拿下面的书时，需要把上面的书先挪走才可以。

如果按照动态规划的方式解决斐波那契数列，我们只需要在计算某个`f(i)`时，将初次计算`f(i)`的结果存储进DP table即可，后续再计算`f(i)`时，可直接查询DP table。如在计算`f(5)`时，通过`f(4)`的递归调用，我们可以按先后顺序，依次求出`f(1)`、`f(2)`、`f(3)`、`f(4)`，再计算`f(3)`时可直接查DP table得到，无须再递归调用。

**注意**：在上述问题求解中，我们是**自顶向下**地进行求解（求`f(5)`，需要求`f(4)`、`f(3)`，以此类推）。而在动态规划问题中，通常都是**自底向上**求解（我们先求`f(1)`、`f(2)`，再求`f(3)`，以此类推），这也是为什么**动态规划一般都脱离了递归，而是由循环迭代完成计算**。

```java
int f(int n){
	int[] table = new int[n+1];
	table[1] = table[2] = 1;
	for(int i = 3; i <= n; i++){
		table[i] = table[i-1]+table[i-2];
	}
	return table[n];
}
```

**斐波那契数列严格来说不是动态规划，因为它没有涉及求最值**。

#### 理解动态规划函数（状态转移方程）

在斐波那契数列中，我们其实可以发现该问题中的状态转移方程就是斐波那契数列的数学表达式，可以将`f(n)`视作一个状态n，这个状态n由状态n-1和状态n-2相加转移而来，这就叫状态转移。

接下来我们再看一个凑零钱的问题：

> 给你`k`种面值的硬币，面值分别为`c1, c2 ... ck`，每种硬币的数量无限，再给一个总金额`amount`，问你**最少**需要几枚硬币凑出这个金额，如果不可能凑出，算法返回 -1 。

比如说`k=3,coins[]={1,2,5},amount=11`，那么最少需要3枚硬币就可凑出（11=5+5+1）。

首先这个问题是动态规划问题，因为它具有**最优子结构**（要符合最优子结构，子问题间必须相互独立）。原问题是“求凑出amount=11的最少硬币数”，如果知道子问题：“凑出amount=10的最少硬币数”（面值最小为1），只需要把子问题的答案加一（再选一枚面值为1的硬币）就是原问题的答案，因为硬币的数量没有限制，子问题之间没有相互制约，是相互独立的。

既然它是一个动态规划问题，那么如何**列出正确的状态转移方程**呢？

1. 先确定**状态**：也就是**原问题和子问题中变化的变量**。由于硬币数量无限，所以唯一的状态就是目标金额`amount`。
2. 然后确定**状态转移方程（动态规划函数）的定义**：函数`dp(n)`表示，当前目标金额是`n`，至少需要`dp(n)`个硬币凑出该金额。
3. 接着确定**状态转移的选择并择优**：也就是**对于每个状态，可以做出什么选择改变当前状态**。具体到这个问题，无论当前状态的目标金额`n`是多少，选择就是从面值列表中依次选择一个面值`ci`，此时金额为`n-ci`，然后选取`dp(n)`的最小值`dp(n)=min{dp(n),dp(n-ci)+1}`。
4. 最后，确定**初始状态**：显然，目标金额`amount=0`时，所需硬币数量为0；当目标金额小于所给硬币的最小面值时，无解，返回-1。如果使用辅助数据结构记录各子问题的解，那么初始时需要设置数据结构的值为相反的最值，如本问题中设置数组`dp[i]`存储金额为`i`所需的最少硬币数，则初始时`dp[i]=MAX_VALUE`（代表一个无穷大值）。

#### 小结

**计算机解决问题其实没有任何奇技淫巧，它唯一的解决办法就是穷举**，穷举所有可能性。算法设计无非就是先思考“如何穷举”，然后再追求“如何聪明地穷举”。

列出动态转移方程，就是在解决“如何穷举”的问题。之所以说它难，一是因为很多穷举需要递归实现，二是因为有的问题本身的解空间复杂，不那么容易穷举完整。

备忘录、DP table 就是在追求“如何聪明地穷举”。用空间换时间的思路，是降低时间复杂度的不二法门。

### 贪心算法

贪心算法在解决问题的策略上目光短浅，只根据当前已有的信息做出选择，而且一旦做出选择，不管将来有什么结果，这个选择都不会改变。

贪心算法其实与动态规划算法类似，是在穷举的基础上，减少冗余计算（和动态规划区别，动态规划是重复计算），而减少的冗余计算是根据算法的“贪心策略”，即贪心算法根据某种策略认定某些子问题的求解是达不到要求的，从而放弃计算这些子问题，最终**求解结果的正确性依赖“贪心策略”是否是正确的、满足要求的**。

*在很多最值问题中，虽然贪心算法不能像动态规划算法般得到最优解，但往往也可以得到一个不错的近似解*。



### 回溯算法

解决**回溯问题，实际上就是一个决策树的遍历过程**。一般需要考虑3个问题：

1. 路径：也就是已经做出的选择
2. 选择列表：也就是你当前可以做的选择
3. 结束条件：也就是到达决策树底层，无法再做选择的条件

回溯算法的框架：

```
result = []
def backtrack(路径, 选择列表):
    if 满足结束条件:
        result.add(路径)
        return

    for 选择 in 选择列表:
        做选择
        backtrack(路径, 选择列表)
        撤销选择
```

**其核心就是for循环里面的递归，在递归调用之前做选择，在递归调用结束之后车撤销选择**，特别简单。

一个严格意义的回溯问题，穷举整棵决策树是无法避免的，这也是回溯算法的一个特点，不像动态规划存在重叠子问题可以优化，回溯算法就是纯暴力穷举，复杂度一般都很高。

回溯算法就是个多叉树（将问题的各种可能结果过程当作一个决策树，关键就在于前序遍历（递归调用之前做选择）和后序遍历（递归调用之后撤销选择）的位置做一些选择：

```
def backtrack(...):
    for 选择 in 选择列表:
        做选择
        backtrack(...)
        撤销选择
```

*写`backtrack`函数时，需要维护走过的路径和当前可以做到的选择列表，当触发结束条件时，将路径计入结果集。*

#### 回溯算法与动态规划算法的联系与区别

其实想想看，回溯算法和动态规划算法有一些相似之处：动态规划算法的三个明确——状态、选择、初始状态，是不是对应着回溯算法中走过的路径，当前的选择列表和结束条件。

某种程度上，动态规划的暴力求解阶段就是回溯算法。只是有的问题具有重叠子问题性质，可以用DP table或者备忘录优化，将递归树大幅剪枝，这就变成了动态规划。而当问题没有重叠子问题时，也就是回溯算法了，复杂度非常高是不可避免的。

### BFS（广度优先搜索）

BFS的**核心思想就是把一些问题抽象成图，从一个点开始，向四周扩散**。一般来说，我们写BFS算法都是用“队列”这种数据结构，每次将一个节点周围的所有节点加入队列。

BFS相对于DFS的最主要区别在于：**BFS找到的路径一定是最短的，但代价就是空间复杂度比DFS大很多**。

#### 使用场景

BFS出现的常见场景：**问题的本质就是让你在一幅“图”中找到从起点start到终点target的最近（短）距离**。

算法实现的基本框架：

```
// 计算从起点 start 到终点 target 的最近距离
int BFS(Node start, Node target) {
    Queue<Node> q; // 核心数据结构
    Set<Node> visited; // 避免走回头路

    q.offer(start); // 将起点加入队列
    visited.add(start);
    int step = 0; // 记录扩散的步数

    while (q not empty) {
        int sz = q.size();
        /* 将当前队列中的所有节点向四周扩散 */
        for (int i = 0; i < sz; i++) {
            Node cur = q.poll();
            /* 划重点：这里判断是否到达终点 */
            if (cur is target)
                return step;
            /* 将 cur 的相邻节点加入队列 */
            for (Node x : cur.adj())
                if (x not in visited) {
                    q.offer(x);
                    visited.add(x);
                }
        }
        /* 划重点：更新步数在这里 */
        step++;
    }
}
```

*说明：队列`q`就不说了，BFS 的核心数据结构；`cur.adj()`泛指`cur`相邻的节点，比如说二维数组中，`cur`上下左右四面的位置就是相邻节点；`visited`的主要作用是防止走回头路，大部分时候都是必须的，但是像一般的二叉树结构，没有子节点到父节点的指针，不会走回头路就不需要`visited`。*

#### 使用原理

1. 为什么BFS可以找到最短距离，DFS不行吗？

   首先，**依据BFS的逻辑，`step`每增加一次代表着当前队列中的所有节点都向前迈了一步，这保证了第一次到达终点的时候，走得步数是最少的**。

   DFS其实也是可以寻找最短路径的，只是时间复杂度相对高很多，因为会产生回溯。DFS实际上是靠递归的堆栈记录走过的路径，要找到最短路径，肯定需要把图中所有的路径都搜索完才能对比出最短的路径。

   BFS借助队列做到了一次一步“齐头并进”，是可以在不遍历完整个图的情况下找到最短路径的。

2. 既然BFS那么好，为啥DFS还要存在？

   BFS可以找到最短路径，但是空间复杂度高，而DFS的空间复杂度较低。

   以[实例分析](#实例分析)中的“二叉树的最小深度”为例，若这棵二叉树是满二叉树，节点总数为N，对于DFS算法来说，空间复杂度无非就是递归堆栈，最环情况下顶多就是树的高度，也就是O(logN)。对于BFS算法来说，队列中每次都会存储二叉树一层的节点，这样的话最坏情况下空间复杂度就是最底层节点的数量，也就是N/2，对应的空间复杂度为O(N)。

   可见BFS还是有代价的，一般来说在**找最短路径的时候使用BFS**，其他时候还是DFS使用的多一些（主要是递归代码好写）。

#### 优化——双向BFS

BFS算法还有一种稍微高级一点的优化思路：双向BFS，可以进一步提高算法的效率。**传统的BFS就是从起点开始向四周扩散，遇到终点时停止；而双向BFS则是从起点和终点同时开始扩散，当两边有交集的时候停止**。

双向BFS的局限性或者说不便之处在于——**必须知道终点在哪里**。

按照 BFS 的逻辑，队列（集合）中的元素越多，扩散之后新的队列（集合）中的元素就越多；在双向 BFS 算法中，如果我们每次都选择一个较小的集合进行扩散，那么占用的空间增长速度就会慢一些，效率就会高一些。从算法空间复杂度的衡量上看，二者的空间复杂度都是O(N)。

### 拓扑排序

用顶点表示活动，用弧表示活动间的优先关系的有向图称为顶点表示活动的网（Activity On Vertex Network），简称AOV-网。

**拓扑排序就是将AOV-网中所有顶点排成一个线性序列，该序列满足：若在AOV网中由顶点Vi到Vj有一条路径（Vi活动完成，Vj活动才能开始），则该线性序列中的顶点Vi必定在顶点Vj之前。**

拓扑排序**过程**：

1. 在有向图中**选择一个无前驱的顶点（入度为0，或者说没有以它为头的弧）加入到拓扑序列（尾插）**中。
2. 在有向图中**删除该顶点和所有以它为尾的弧**。
3. 重复1和2，**直到有向图中不存在无前驱的顶点**。
4. 若此时**拓扑序列中顶点数小于原有向图中的顶点数，说明原有向图中存在环**；否则，此时的拓扑序列就是原有向图的一个拓扑序列（**对于有向无环图来说，拓扑序列不唯一**）。

拓扑排序的应用场景：

+ 判断有向图是否存在环
+ 给出一项工程（或事件）中各项活动的进行次序，如请给出课程的修读次序

#### 拓扑排序与深度优先搜索（后序遍历）的关系

对于有向无环图：**将后序遍历的结果反转，就是拓扑排序的序列**。



## 拓展的数据结构

### 堆（Heap）

堆（heap）的定义：n个元素的序列{k~1~，k~2~，k~3~，……，k~n~}称之为堆，当且仅满足以下条件时：

+ 大根堆：k~i~≥k~2i~且k~i~≥k~2i+1~（1≤i≤$\lfloor n/2 \rfloor$​）。

  如果将序列{k~1~，k~2~，k~3~，……，k~n~}看做一棵完全二叉树，则大根堆对应的完全二叉树满足双亲节点大于等于左、右孩子节点，根结点是序列中最大的关键字。

+ 小根堆：k~i~≤k~2i~且k~i~≤k~2i+1~（1≤i≤$\lfloor n/2 \rfloor$​）。

  如果将序列{k~1~，k~2~，k~3~，……，k~n~}看做一棵完全二叉树，则小根堆对应的完全二叉树满足双亲节点小于等于左、右孩子节点，根结点是序列中最小的关键字。

*完全二叉树的性质或特点：1.叶子节点只可能出现在层次最大的两层（最后两层）。2.最多只有一个度为1的节点。3.节点i的左孩子为2i，右孩子为2i+1；节点i的双亲节点为$\lfloor i/2 \rfloor$。4.i≤$\lfloor n/2 \rfloor$为分支节点（非叶子节点），i＞$\lfloor n/2 \rfloor$为叶子节点。*

堆一般涉及两个操作：1. 建堆。2. 调整堆。

#### 建堆（以大根堆为例）

建堆的目的是为了将一个无序的序列建成一个大根堆（不完全升序的序列）。

思想就是将无序序列对应的**完全二叉树**以每一个节点为根的子树都**调整为堆**。所以在建堆的过程中需要调用调整堆的操作。

#### 调整堆（以大根堆为例）

比较直接的方式是通过“筛选法”去调整堆。

显然地，每一个叶子节点一定是堆（无论是大根堆还是小根堆），由完全二叉树的性质知编号（将完全二叉树向满二叉树映射过程中给每一个节点编号，从1到n）大于$\lfloor n/2 \rfloor$的节点是叶子结点，因此只需要调整编号为1～$\lfloor n/2 \rfloor$的节点，使其及其孩子节点（子树）为大根堆。

从最后一个分支节点（非叶节点）$\lfloor n/2 \rfloor$开始，按照：

1. 若k~i~≥k~2i~且k~i~≥k~2i+1~，则不对k~i~及其子树做调整，因为它满足大根堆的定义。
2. 若k~i~＜max{k~2i~，k~2i+1~}，则将k~i~和max{k~2i~，k~2i+1~}交换（交换序列中两个位置的关键字）。若交换后新的以k~2i~或k~2i+1~为根的树不是堆，则重复上述操作，直到子树为堆为止。

依次将编号为$\lfloor n/2 \rfloor$、$\lfloor n/2 \rfloor$-1、……，1的节点作为根的子树调整为大根堆。

#### 应用

堆一般应用在对一维序列进行排序中，即所谓的”堆排序“，因为堆对应的完全二叉树的根结点一定是最大或最小的关键字，取走根结点后，调用调整堆的操作恢复堆，继续取根结点，继续调整堆，直到堆为空，而取走的根结点按照取走的先后顺序会组成有序序列（即排序）。



## 特定场景下的数据数据结构与算法

### 单调栈

单调栈与一般栈的特点：**栈内的元素保持升序或者降序**。

#### 使用场景

***通常是一维数组或序列，要寻找任一元素的右边或者左边第一个比自己大或者小的元素的位置***，此时我们就要想到可以用单调栈了。时间复杂度为O(n)。

例如：

请根据每日气温列表，重新生成一个列表。对应位置的输出为：要想观测到更高的气温，至少需要等待的天数。如果气温在这之后都不会升高，请在该位置用 0 来代替。

*[LeetCode链接](https://leetcode-cn.com/problems/daily-temperatures/)*

示例：

给定一个列表 temperatures = [73, 74, 75, 71, 69, 72, 76, 73]，你的输出应该是 [1, 1, 4, 2, 1, 1, 0, 0]。

#### 使用原理

单调栈的本质是利用空间换时间，因为在遍历的过程中需要**使用一个栈来记录右边或者左边第一个比当前遍历元素大或者小的元素，优点是只需要遍历一次**。

在使用单调栈的时候首先要明确如下几点：

1. 单调栈里存放的元素是什么？

   单调栈里通常只需要存放元素的下标i就可以，如果需要使用对应的元素，直接T[i]就可以获取。特殊情况下，根据算法设计的需要也可以直接存放元素。

2. 单调栈里元素是递增呢？还是递减？

   **注意一下顺序通常为从栈头（顶）到栈底的顺序**，因为单纯的说从左到右或者从前到后，不说栈头朝哪个方向的话，容易有歧义。

   以“每日温度”题目为例，这里我们要使用递增顺序（从栈头到栈底），因为只有递增的时候，加入一个元素i，才知道栈顶元素在数组中右面第一个比栈顶元素大的元素是i。

3. 遍历顺序是从前向后还是从后向前？

   从前向后：以数组为例——从下标0开始向下标length-1遍历

   从后向前：以数组为例——从下标length-1开始向下标0遍历

**使用单调栈主要有三个判断条件**。

+ 当前遍历的元素T[i]小于栈顶元素T[st.top()]的情况
+ 当前遍历的元素T[i]等于栈顶元素T[st.top()]的情况
+ 当前遍历的元素T[i]大于栈顶元素T[st.top()]的情况

在遍历数组的时候，遍历可以从下标0开始向后遍历，也可以从下标length-1开始向前遍历。

如果规定**栈为单调递增**（从栈顶到栈底）的，栈内存放数组下标，**从数组下标0开始向后遍历数组**：

+ 栈为空，当前遍历的元素T[i]直接入栈。
+ 当前遍历的元素T[i]小于栈顶元素T[st.top()]，当前元素T[i]入栈：保证栈是单调递增的。T[i]和T[st.top()]的关系：i>st.top()，T[i]<T[st.top()]，**T[i]是T[st.top()]右边第一个小于自己的元素**，也可以说**T[st.top()]是T[i]左边第一个大于自己的元素**。
+ 当前遍历的元素T[i]等于栈顶元素T[st.top()]，此时需要根据题目要求和自己设计的算法判断T[i]是否应该入栈。
+ 当前遍历的元素T[i]大于栈顶元素T[st.top()]，栈顶元素T[st.top()]出栈：保证栈是单调递增的，T[i]和T[st.top()]的关系：i>st.top()，T[i]>T[st.top()]，**T[i]是T[st.top()]右边第一个大于自己的元素**，也可以说**T[st.top()]是T[i]左边第一个小于自己的元素**；T[i]继续和下一个栈顶元素T[st.top()]比较，直到T[i]不大于栈顶元素T[st.top()]或栈为空，T[i]入栈。

如果规定**栈为单调递增**（从栈顶到栈底）的，栈内存放数组下标，**从数组下标length-1开始向前遍历数组**：

+ 栈为空，当前遍历的元素T[i]直接入栈
+ 当前遍历的元素T[i]小于栈顶元素T[st.top()]，当前元素T[i]入栈：保证栈是单调递增的。T[i]和T[st.top()]的关系：i<st.top()，T[i]<T[st.top()]，**T[i]是T[st.top()]左边第一个小于自己的元素**，也可以说**T[st.top()]是T[i]右边第一个大于自己的元素**。
+ 当前遍历的元素T[i]等于栈顶元素T[st.top()]，此时需要根据题目要求和自己设计的算法判断T[i]是否应该入栈。
+ 当前遍历的元素T[i]大于栈顶元素T[st.top()]，栈顶元素T[st.top()]出栈：保证栈是单调递增的，T[i]和T[st.top()]的关系：i<st.top()，T[i]>T[st.top()]，**T[i]是T[st.top()]左边第一个大于自己的元素**，也可以说**T[st.top()]是T[i]右边第一个小于自己的元素**；T[i]继续和下一个栈顶元素T[st.top()]比较，直到T[i]不大于栈顶元素T[st.top()]或栈为空，T[i]入栈。

其他的情况（栈为单调递减，数组遍历方向不同），可以自行分析。

其实使用单调栈主要是因为**栈内元素的单调性（递增或递减）**可以帮助我们解决求解“某个序列中元素的左边或右边**第一个**大于或小于自己的元素”的问题，而**这种单调性是通过遍历序列得到的**，在遍历序列的过程中，我们应该十分清楚的知道**当前元素与栈内元素的（通常是栈顶元素）的大小关系**与**“左边或右边第一个大于或小于自己的元素”**之间的联系这才是最重要的，利用这二者的联系去帮助我们设计算法。

**注意：我们应该是“设计算法，使用数据结构去实现算法“，而不是”设计数据结构，套用模板去实现算法“。**

#### 实例分析

接下来我们用“每日温度”的例子来逐步分析，取输入用例temperature=[73,74,75,71,71,72,76,73]，输出应该为[1,1,4,2,1,1,0,0]。

对数组temperature的**遍历顺序是从前先后（从下标0开始）**，单调栈（**单调递增**）存放的是数组下标，用与temperature等长的数组result记录输出结果。

1. 首先第一个遍历元素是73，此时栈为空，单调栈加入的是73的数组下标0。
2. 遍历元素74，74>T[0]（73）（**当前遍历的元素T[i]大于栈顶元素T[st.top()]的情况：T[i]是T[st.top()]右边第一个大于自己的元素**），而我们要保持一个单调递增栈（从栈头到栈底），所以T[0]（73）弹出，T[1]（74）加入，此时result数组可以记录——result[0]=1-0=1，即T[0]（73）右面第一个比T[0]大的元素是T[1]（74）。
3. 遍历元素75，75>T[1]（74），T[1]（74）弹出，T[2]（75）加入，此时result记录result[1]=2-1=1。
4. 遍历元素71，71<T[2]（75）（当前遍历的元素T[i]小于栈顶元素T[st.top()]的情况），加入T[3]（71）到单调栈。
5. 遍历元素71，71=T[3]（71）（当前遍历的元素T[i]等于栈顶元素T[st.top()]的情况），此时依然要加入栈，不用计算距离，因为我们需要求的是右面第一个大于本元素的位置，而不是大于等于。
6. 遍历元素72，72>T[4]（71），将T[4]（71）出栈，result记录——result[4]=5-4=1。又72>T[3]（71），T[3]（71）出栈，T[5]（72）入栈，result记录——result[3]=5-3=2。
7. 遍历元素76，76>T[5]（72），将T[5]（72）出栈，result记录——result[5]=6-5=1；又76>T[2]（75），将T[2]（75）出栈，T[6]（76入栈），result记录——result[2]=6-2=4。
8. 遍历元素73，73<T[6]（76），将T[7]（73）入栈。

因为数组在定义时自动初始化为0，所以未计算的result数组元素为0（result[6]=0，result[7]=0），是符合要求的。

### 并查集（Union-Find算法）

并查集算法主要解决图论中的**动态连通性问题**。

简单说，动态连通性其实可以抽象成给一幅图连线。比如在一个图（无向图）中有编号为0~9的10个顶点，初始时它们互不相连（连通），即连通分量为10。现在请根据邻接矩阵`edge[10][10]`，计算图中实际的连通分量。可看作给图中的顶点按照邻接矩阵连线，然后计算各不相连（不连通）的顶点集个数。

这里说的**连通**是一种等价关系，具有如下三个性质：

1. 自反性：节点p和p是连通的
2. 对称性：如果节点p和q是连通的，那么q和p是连通的
3. 传递性：如果节点p和q连通，q和r连通，那么p和r也连通

判断这种**连通关系**很实用，比如编译器判断同一个变量的不同引用，比如社交网络中的朋友圈计算等。

动态连通性就是对顶点两两判断连通，然后相连（合并连通分量）。

并查集算法（Union-Find算法）主要实现以下功能：

1. 查找节点p的连通分量：`find(p)`
2. 将节点p和q连接：`union(p,q)`
3. 判断节点p和q是否连通：`connected(p,q)`

并查集算法的关键在于`union`和`connected`的效率。

#### 使用场景

本质就是计算在**一个图中的连通分量数量**。也可以演变成**查找某个元素（顶点）所处的集合（连通分量）**——`find(p)`、**某两个元素是否属于同一集合**——`connected(p,q)`。

#### 使用原理

我们将图视作一个**森林**，图中的每个连通分量对应森林中的一棵**树**，使用数组来存储这个森林（图）中的节点信息，比如`node[i]`代表编号为i的节点（顶点）。为了表示图中的连通分量，也即森林中的每个节点所属的树，我们设定树的每个节点有一个指向所属树根节点的指针，如`parent[i]=j`表示编号为i的节点（顶点）属于根节点编号为j的树（看作该连通分量中所有的顶点都与编号为j的顶点连通，不同的连通分量之间以此区分）。

在初始时，先设节点没有互相连通，此时连通分量为节点总数，`parent[i]=i`，即各个顶点各为一个连通分量。

```
class UF {
    // 记录连通分量
    private int count;
    // 节点x的根节点是 parent[x]
    private int[] parent;

    /* 构造函数，n 为图的节点总数 */
    public UF(int n) {
        // 一开始互不连通
        this.count = n;
        // 根节点指针初始指向自己
        parent = new int[n];
        for (int i = 0; i < n; i++)
            parent[i] = i;
    }

    /* 其他函数 */
}
```

如果某两个节点连通，则让其中的（任意）一个节点的根节点接到另一个节点的根节点上（类似将森林中的两个棵树合并为一棵树）。

```
public void union(int p, int q) {
    int rootP = find(p);
    int rootQ = find(q);
    if (rootP == rootQ)
        return;
    // 将两棵树合并为一棵
    parent[rootP] = rootQ;
    // parent[rootQ] = rootP 也一样
    count--; // 两个分量合二为一
}

/* 返回某个节点 x 的根节点 */
private int find(int x) {
    // 根节点的 parent[x] == x
    while (parent[x] != x)
        x = parent[x];
    return x;
}

/* 返回当前的连通分量个数 */
public int count() { 
    return count;
}
```

*说明：现在有两个连通分量：[0,2,5]——parent[0]=0，parent[2]=0，parent[5]=0；[1,4,9]——parent[1]=1，parent[4]=1，parent[9]=1。将第二个分量按上述代码的方式合并到第一个分量后，只有一个连通分量：[0,1,2,4,5,9]——parent[0]=0，parent[1]=0，parent[2]=0，parent[4]=1，parent[5]=0，parent[9]=1。注意，此时的4和9的parent没有更改，依旧指向1，而1的parent则更改为了0。*

这样，如果节点p和q连通的话，他们一定有相同的根节点：

```
public boolean connected(int p, int q) {
    int rootP = find(p);
    int rootQ = find(q);
    return rootP == rootQ;
}
```

到这里，并查集算法 （Union-Find算法）就基本实现了。常用的就是`union`——合并连通分量，`find`——查询顶点的连通分量，`connected`——判断两个顶点是否属于一个连通分量 。

算法分析：我们发现无论是`union`还是`connected`都是调用`find`，可见算法的复杂度主要是`find`引起的，即**怎样查找一个顶点所属的连通分量**。在上述实现中，我们是通过从一个节点向上搜索到根节点完成的，所以时间复杂度就是代表连通分量的树的高度。对于一棵N个节点的树（不一定是二叉树）而言，树的高度最大是N，最小是2（N>1)，若是一棵二叉树可能是logN（平衡二叉树）。综上，`find`的时间复杂度应该为O(N)，相应的`union`和`connected`的时间复杂度也为O(N)。

可见若要降低算法的时间复杂度，我们应该使查找一个顶点所属的连通分量的时间尽可能短。按照上述实现的数据结构`parent[i]=j`，每个连通分量在初始的时候，其实都是O(1)就能完成查找，因为此时连通分量中的顶点`n`都直接指向根节点`m`，`parent[n]=m {n属于连通分量m}`，即可视连通分量m的对应的树是一棵高为2的树，根节点的扇出很大。可随着连通分量之间的合并（如按照上述方式仅修改被合并树的根结点指针，且任意选择被合并树），就可能导致树的高度不断增加，查找连通分量花费更多的时间。

#### 算法优化

##### 平衡性优化

在前述，我们已经知道了导致算法时间开销大的主要原因是`union`——连通分量的合并上，如果我们能够使得合并后的连通分量的树高尽可能小，会提高`find`——查找连通分量的树的根节点效率。

如有连通分量：[0,1]和[2]，其中{parent[0]=1,parent[1]=1}，{parent[2]=2}，在合并时可选择将[0,1]合并到[2]，或将[2]合并到[0,1]。

+ 将[0,1]合并到[2]：合并后，[0,1,2]——{parent[0]=1,parent[1]=2,parent[2]=2}，树高为3。
+ 将[2]合并到[0,1]：合并后，[0,1,2]——{parent[0]=1,parent[1]=1,parent[2]=1}，树高为2。

平衡性优化就是我们希望，小一些的树接到大一些的树下面就能避免“头重脚轻”，更平衡一些。解决的方法就是使用一个`size[]`数组，记录每棵树包含的节点数：

```
class UF {
    private int count;
    private int[] parent;
    // 新增一个数组记录树的节点数
    private int[] size;

    public UF(int n) {
        this.count = n;
        parent = new int[n];
        // 最初每棵树只有一个节点
        // 重量应该初始化 1
        size = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }
    }
    
    public void union(int p, int q) {
    	int rootP = find(p);
    	int rootQ = find(q);
    	if (rootP == rootQ)
        	return;

    	// 小树接到大树下面，较平衡
    	if (size[rootP] > size[rootQ]) {
        	parent[rootQ] = rootP;
        	size[rootP] += size[rootQ];
    	} else {
        	parent[rootP] = rootQ;
        	size[rootQ] += size[rootP];
    	}
    	count--;
	}
    /* 其他函数 */
    
}
```

通过这种方式，可以保证树生长的相对平衡一些，树的高度大致在`logN`这个数量级，此时算法时间复杂度为O(logN)。

##### 路径压缩

在算法分析的时候，我们说过：

>每个连通分量在初始的时候，其实都是O(1)就能完成查找，因为此时连通分量中的顶点`n`都直接指向根节点`m`，`parent[n]=m {n属于连通分量m}`，即可视连通分量m的对应的树是一棵高为2的树，根节点的扇出很大。

所以我们只需要将一个连通分量中的所有顶点都指向根节点，那么就可以做到O(1)常数级下的查找性能。

无论是`union`还是`connected`都调用了`find`，而`find`就是从一个节点向上搜索根节点，所以可以在`find`中修改：

```
private int find(int x) {
    while (parent[x] != x) {
        // 进行路径压缩
        parent[x] = parent[parent[x]];
        x = parent[x];
    }
    return x;
}
```

在压缩时`parent[x] = parent[parent[x]]`使得`x`的`parent`指向了其父节点的父节点`grandpa`，而后将`grandpa`复制给`x`继续压缩。

每调用一次`find`都会进行压缩，随着`union`和`connected`的不断调用，最终所有的树高都不会超过3（通常多次压缩后树高为2，但在合并时可能会导致树高为3）。此时`find`的执行时间是常数级O(1)。

##### 优化后代码

```
class UF {
    // 连通分量个数
    private int count;
    // 存储一棵树
    private int[] parent;
    // 记录树的“节点数”
    private int[] size;

    public UF(int n) {
        this.count = n;
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }
    }

    public void union(int p, int q) {
        int rootP = find(p);
        int rootQ = find(q);
        if (rootP == rootQ)
            return;

        // 小树接到大树下面，较平衡
        if (size[rootP] > size[rootQ]) {
            parent[rootQ] = rootP;
            size[rootP] += size[rootQ];
        } else {
            parent[rootP] = rootQ;
            size[rootQ] += size[rootP];
        }
        count--;
    }

    public boolean connected(int p, int q) {
        int rootP = find(p);
        int rootQ = find(q);
        return rootP == rootQ;
    }

    private int find(int x) {
        while (parent[x] != x) {
            // 进行路径压缩
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }
}
```



### 双指针

#### 快慢指针

快慢指针主要**解决链表中的问题**，包括但不限于典型的判定链表中是否包含环。

快慢指针一般都初始化指向链表的头结点head，前进时快指针`fast`在前，慢指针`slow`在后，巧妙解决一些链表中的问题。

##### 判定链表中是否含有环

单链表的特点是每个结点有且仅有一个指针域，指针域指向下一个结点，但是只有一个指针是无法判断链表中是否含有环的。

如果链表不含坏，那么这个指针最终会遇到空指针`null`表示链表到“头”了，可以很简单的判断该链表不含环：

```
boolean hasCycle(ListNode head) {
    while (head != null)
        head = head.next;
    return false;
}

```

但如果链表中含有环，那么上述代码就会陷入死循环，因为在含环的链表中没有`null`指针作为尾部的结点。

经典的解法就是用两个指针，一个每次前进两步（快指针），一个每次前进一步（慢指针）。如果不含环，快指针会最终遇到`null`指针，说明链表不含环；如果含环，快指针最终会超慢指针一圈，最后和慢指针相遇（此时快指针比慢指针多走一圈），说明链表含环。

```
boolean hasCycle(ListNode head) {
	ListNode fast,slow;
	fast = slow = head;
    while (fast != null && fast.next != null){
    	fast = fast.next.next;
    	slow = slow.next;
    	if(fast == slow){
    		return true;
    	}
    }
    return false;
}

```

##### 已知链表中含有环，返回这个环的起始位置

这个问题其实不难，只是有点不易理解。我们可以当快慢指针相遇时，让其中一个指针重新指向头结点，然后让他俩以相同的速度前进，再次相遇时所处的结点位置就是环开始的位置。

```
ListNode detectCycle(ListNode head) {
	ListNode fast,slow;
	fast = slow = head;
    while (fast != null && fast.next != null){
    	fast = fast.next.next;
    	slow = slow.next;
    	if(fast == slow){
    		break;
    	}
    }
    slow = head;
    while(slow != fast){
    	fast = fast.next;
    	slow = slow.next;
    }
    return slow;
}

```

**解释**：第一次相遇时，假设慢指针slow走了K步，那么快指针fast一定走了2k步（因为fast一次前进两步），也就是说fast比slow多走了k步（这k步也就是环的长度）。设相遇点距环的起始点的距离为m，那么环的起始点距头结点head的距离为k-m，也就是说如果从head前进k-m步就可以到达环的起始点。巧的是，如果从相遇点继续前进k-m步，也恰好达到环的起始点。所以，只要我们把快慢指针中的任一个重新指向head，然后两个指针同速前进，k-m步后就会相遇，相遇之处就是环的起点了。

##### 寻找链表的中点

类似上面的思路，我们可以让快指针一次前进2步，慢指针一次前进1步，当快指针到达链表尽头时，慢指针就处于链表的中间位置。

```
ListNode fast,slow;
slow = fast = head;
while(fast != null && fast.next != null){
	fast = fast.next.next;
	slow = slow.next;
}
return slow;
```

当链表的长度为奇数（2k-1）时，fast指针最后一次指向链表的最后一个结点`2k-1`（从1开始编号），fast共走了k-1步，则slow此时恰好指向中间结点`k`。

当链表的长度为偶数（2k）时，fast指针最后一次指向链表的结点`2k+1`（从1开始编号，2k+1实际上是null，即最后一个结点`2k`的指针域），fast共走了k步，slow此时指向链表的结点`k+1`，即链表中间的两个节点中偏右（靠近尾结点）的那个结点。

*寻找链表中点的一个重要作用是对链表进行归并排序，即完成对链表的二分。*

##### 寻找链表的倒数第k个元素

还是使用快慢指针，让快指针先走k步，然后快慢指针开始同速前进。这样当快指针走到链表末尾null时，慢指针所在的位置就是链表倒数第k个链表结点（为了简化，假设k不会超过链表长度）：

```
ListNode fast,slow;
slow = fast = head;
while(k-- > 0){
	fast = fast.next;
}
while(fast != null){
	fast = fast.next;
	slow = slow.next;
}
return slow;
```

左右指针主要**解决数组（或者字符串）中的问题**，如二分查找（折半查找）。

左右指针在数组中实际是指向两个索引值，一般初始化为`left=0,right=nums.length-1`。

##### 二分查找

一个简单的二分查找：

```
int binarySearch(int[] nums,int target){
	int left = 0;
	int right = nums.length;
	while(left <= right){
		int mid = (left+right)/2;
		if(nums[mid] == target){
			return mid;
		}else if(nums[mid] < target){
			left = mid+1;
		}else{
			right = mid-1;
		}
	}
	return -1;
}
```

#### 滑动窗口

滑动窗口可以解决很多与**子字符串匹配**的问题。

滑动窗口的思路非常简单，就是**维护一个窗口，不断滑动，然后更新答案**。该算法的大致思路：

```
int left = 0, right = 0;

while (right < s.size()) {
    // 增大窗口
    window.add(s[right]);
    right++;

    while (window needs shrink) {
        // 缩小窗口
        window.remove(s[left]);
        left++;
    }
}
```

这个算法的时间复杂度是O(N)，比一般的字符串暴力算法要高效得多。

其实在实际应用中，难的不是算法思路，而是各种细节问题。比如说如何向窗口中添加新元素，如何缩小窗口，在窗口滑动的那个阶段更新结果。即便明白了这些细节，也容易出bug，找bug还不知道怎么找，真的挺让人心烦的。

##### 最小覆盖子串

[76. 最小覆盖子串 - 力扣（LeetCode）](https://leetcode.cn/problems/minimum-window-substring/description/)

题目：

> 给你一个字符串 `s` 、一个字符串 `t` 。返回 `s` 中涵盖 `t` 所有字符的最小子串。如果 `s` 中不存在涵盖 `t` 所有字符的子串，则返回空字符串 `""` 。
>
> - 对于 `t` 中重复字符，我们寻找的子字符串中该字符数量必须不少于 `t` 中该字符数量。
> - 如果 `s` 中存在这样的子串，我们保证它是唯一的答案。

示例：

>输入：s = "ADOBECODEBANC", t = "ABC"
>输出："BANC"
>解释：最小覆盖子串 "BANC" 包含来自字符串 t 的 'A'、'B' 和 'C'。

使用暴力解法，代码可能如下：

```
for (int i = 0; i < s.size(); i++)
    for (int j = i + 1; j < s.size(); j++)
        if s[i:j] 包含 t 的所有字母:
            更新答案
```

思路很直接，但是显然，算法的时间复杂度很高。

滑动窗口的思路是这样的：

1. 我们在字符串`s`中使用左右指针的技巧，初始化`left = right = 0`，**把索引左闭右开区间`[left,right)`称为一个窗口**。
2. 先不断地增加`right`指针扩大窗口`[left,right)`，直到窗口中的字符串符合要求（包含了`t`中的所有字符）。
3. 此时，停止增加`right`，转而不断增加`left`指针缩小窗口`[left,right)`，直到窗口中的字符串不再符合要求（不包含`t`中的所有字符了）。同时，每次增加`left`，都要更新一轮结果。
4. 重复第2和第3步，直到`right`到达字符串`s`的尽头。

这个思路其实不难理解，第2步相当于寻找一个可行解，然后第3步在优化这个可行解，最终找到最优解，也就是最短的覆盖子串。

左右指针轮流前进，窗口大小增增减减，窗口不断向右滑动，这就是滑动窗口名字的来历。

```
string minWindow(string s, string t) {
    unordered_map<char, int> need, window;
    for (char c : t) need[c]++;

    int left = 0, right = 0;
    int valid = 0;
    // 记录最小覆盖子串的起始索引及长度
    int start = 0, len = INT_MAX;
    while (right < s.size()) {
        // c 是将移入窗口的字符
        char c = s[right];
        // 右移窗口
        right++;
        // 进行窗口内数据的一系列更新
        if (need.count(c)) {
            window[c]++;
            if (window[c] == need[c])
                valid++;
        }

        // 判断左侧窗口是否要收缩
        while (valid == need.size()) {
            // 在这里更新最小覆盖子串
            if (right - left < len) {
                start = left;
                len = right - left;
            }
            // d 是将移出窗口的字符
            char d = s[left];
            // 左移窗口
            left++;
            // 进行窗口内数据的一系列更新
            if (need.count(d)) {
                if (window[d] == need[d])
                    valid--;
                window[d]--;
            }                    
        }
    }
   // 返回最小覆盖子串
    return len == INT_MAX ?
        "" : s.substr(start, len);
}
```



##### 字符串排列

[567. 字符串的排列 - 力扣（LeetCode）](https://leetcode.cn/problems/permutation-in-string/description/)

题目：

>给你两个字符串 `s1` 和 `s2` ，写一个函数来判断 `s2` 是否包含 `s1` 的排列。如果是，返回 `true` ；否则，返回 `false` 。
>
>换句话说，`s1` 的排列之一是 `s2` 的 **子串** 。

示例：

> 输入：s1 = "ab" s2 = "eidbaooo"
> 输出：true
> 解释：s2 包含 s1 的排列之一 ("ba").

> 输入：s1= "ab" s2 = "eidboaoo"
> 输出：false

这种题目，是明显的滑动窗口算法，相当于给你一个`s`和`t`，请问你`s`中是否存在一个子串包含`t`中所有字符且不包含其他字符？

对于这道题的解法代码，基本上与最小覆盖子串一模一样，只需要改变两个地方：

1. 本题移动`left`缩小窗口的时机是窗口大小大于`t.size()`时，因为排列嘛，显然长度应该是一样的
2. 当发现`valid == need.size()`时，就说明窗口中就是一个合法的排列，所以立即返回true。

至于如何处理窗口的扩大和缩小，和最小覆盖子串完全相同。

```
// 判断 s 中是否存在 t 的排列
bool checkInclusion(string t, string s) {
    unordered_map<char, int> need, window;
    for (char c : t) need[c]++;

    int left = 0, right = 0;
    int valid = 0;
    while (right < s.size()) {
        char c = s[right];
        right++;
        // 进行窗口内数据的一系列更新
        if (need.count(c)) {
            window[c]++;
            if (window[c] == need[c])
                valid++;
        }

        // 判断左侧窗口是否要收缩
        while (right - left >= t.size()) {
            // 在这里判断是否找到了合法的子串
            if (valid == need.size())
                return true;
            char d = s[left];
            left++;
            // 进行窗口内数据的一系列更新
            if (need.count(d)) {
                if (window[d] == need[d])
                    valid--;
                window[d]--;
            }
        }
    }
    // 未找到符合条件的子串
    return false;
}
```

这道题其实很简单，一般来说就是当`right`增加的时候，判断新加入子串的字符是否已经在字符串`s`中存在，若存在，应该缩小窗口——`left`增加，直到使得新加入的字符是首次出现；若不存在，则加入窗口，`right`继续增加。

```
int lengthOfLongestSubstring(string s) {
    unordered_map<char, int> window;

    int left = 0, right = 0;
    int res = 0; // 记录结果
    while (right < s.size()) {
        char c = s[right];
        right++;
        // 进行窗口内数据的一系列更新
        window[c]++;
        // 判断左侧窗口是否要收缩
        while (window[c] > 1) {
            char d = s[left];
            left++;
            // 进行窗口内数据的一系列更新
            window[d]--;
        }
        // 在这里更新答案
        res = max(res, right - left);
    }
    return res;
}
```

### 前缀和

#### 一维数组中的前缀和

```java
}
```

这样，可以达到效果，但是效率很差，因为`sumRange`方法会被频繁调用，而它的时间复杂度为O(N)，其中N为`nums`数组的长度。

此题的最优解法就是使用前缀和技巧，将`sumRange`函数的时间复杂度降为O(1)。而**前缀和技巧就是用空间换时间，使用一个数据结构（如数组）去存储“前缀和”，替换掉`sumRange`方法中的`for`循环**。

```java
class NumArray {
    // 前缀和数组
    private int[] preSum;

    /* 输入一个数组，构造前缀和 */
    public NumArray(int[] nums) {
        // preSum[0] = 0，便于计算累加和
        preSum = new int[nums.length + 1];
        // 计算 nums 的累加和
        for (int i = 1; i < preSum.length; i++) {
            preSum[i] = preSum[i - 1] + nums[i - 1];
        }
    }

    /* 查询闭区间 [left, right] 的累加和 */
    public int sumRange(int left, int right) {
        return preSum[right + 1] - preSum[left];
    }
}
```

**说明**：`preSum[i]`记录`nums[0……i-1]`的累加和，也即数组中索引小于i的所有元素和。

*注：关于前缀和数组的定义，可以按照自己的思路去定义，只要能够帮助解决问题即可。如我们完全可以令`preSum[i]`为数组中索引小于等于i的所有元素之和。再次提醒自己——算法思想是活的，不要让算法设计失去自己的灵魂。*

#### 二维矩阵中的前缀和

[304. 二维区域和检索 - 矩阵不可变 - 力扣（LeetCode）](https://leetcode.cn/problems/range-sum-query-2d-immutable/description/)

题目：

>给定一个二维矩阵 `matrix`，以下类型的多个请求：
>- 计算其子矩形范围内元素的总和，该子矩阵的 **左上角** 为 `(row1, col1)` >，**右下角** 为 `(row2, col2)` 。
>实现 `NumMatrix` 类：
>- `NumMatrix(int[][] matrix)` 给定整数矩阵 `matrix` 进行初始化
>- `int sumRegion(int row1, int col1, int row2, int col2)` 返回 >**左上角** `(row1, col1)` 、**右下角** `(row2, col2)` 所描述的子矩阵的元素 **总和** 。

示例：

>输入: 
>["NumMatrix","sumRegion","sumRegion","sumRegion"]
>[[[[3,0,1,4,2],[5,6,3,2,1],[1,2,0,1,5],[4,1,0,1,7],[1,0,3,0,5]]],[2,1,4,3],[1,1,2,2],>[1,2,2,4]]
>输出: 
>[null, 8, 11, 12]
>
>![](.\images\二维数组前缀和示例.jpg)
>
>解释：
>
>NumMatrix numMatrix = new NumMatrix([[3,0,1,4,2],[5,6,3,2,1],[1,2,0,1,5],[4,1,0,1,7],[1,0,3,0,5]]);
>numMatrix.sumRegion(2, 1, 4, 3); // return 8 (红色矩形框的元素总和)
>numMatrix.sumRegion(1, 1, 2, 2); // return 11 (绿色矩形框的元素总和)
>numMatrix.sumRegion(1, 2, 2, 4); // return 12 (蓝色矩形框的元素总和)

这题的思路和一维数组中的前缀和是非常类似的。如果我们现在需要计算的是`sumRegion(2,1,4,3)`，即下图中红色的子矩阵：
![](.\images\二维数组前缀和分析设计.jpg)

要计算红色的这个子矩阵的元素之和，可以用绿色矩阵减去蓝色矩阵、再减去橙色矩阵，最后加上粉色矩阵（因为粉色矩阵被多减了一次）。这些矩阵（绿、蓝、橙、粉）有一个共同的特点，就是左上角的元素下标为（0，0）。

那么我们可以维护一个二维数组`preSum[i,j]`，专门记录以（0，0）为左上角、（i-1，j-1）为右下角的矩阵区域的所有元素之和，这就是此题二维数组中的“前缀和数组”。

```java
class NumMatrix {
    // preSum[i][j] 记录矩阵 [0, 0, i, j] 的元素和
    private int[][] preSum;

    public NumMatrix(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        if (m == 0 || n == 0) return;
        // 构造前缀和矩阵
        preSum = new int[m + 1][n + 1];
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // 计算每个矩阵区域 [0, 0, i-1, j-1] 的元素和
                preSum[i][j] = preSum[i-1][j] + preSum[i][j-1] + matrix[i - 1][j - 1] - preSum[i-1][j-1];
            }
        }
    }

    // 计算子矩阵 [x1, y1, x2, y2] 的元素和
    public int sumRegion(int x1, int y1, int x2, int y2) {
        // 目标矩阵之和由四个相邻矩阵运算获得
        return preSum[x2+1][y2+1] - preSum[x1][y2+1] - preSum[x2+1][y1] + preSum[x1][y1];
    }
}
```

**说明**：关于前缀和数组`preSum[i,j]`的定义一定要自己清楚，易于自己解决问题，不要过分的遵循上述代码。

此题通过前缀和数组，也使得`sumRegion`函数的复杂度降到了O(1)。

#### 和为k的子数组

[560. 和为 K 的子数组 - 力扣（LeetCode）](https://leetcode.cn/problems/subarray-sum-equals-k/description/)

题目：

> 给你一个整数数组 `nums` 和一个整数 `k` ，请你统计并返回 *该数组中和为 `k` 的子数组的个数* 。
>
> 子数组是数组中元素的连续非空序列。

示例：

>输入：nums = [1,1,1], k = 2
>输出：2
>
>输入：nums = [1,2,3], k = 3
>输出：2

一个简单的做法就是将所有的子数组都穷举出来，算它们的和谁等于`k`不就行了，借助前缀和技巧很容易写出一个解法：

```java
int subarraySum(int[] nums, int k) {
    int n = nums.length;
    // 构造前缀和
    int[] preSum = new int[n + 1];
    preSum[0] = 0; 
    for (int i = 0; i < n; i++)
        preSum[i + 1] = preSum[i] + nums[i];

    int res = 0;
    // 穷举所有子数组
    for (int i = 1; i <= n; i++)
        for (int j = 0; j < i; j++)
            // 子数组 nums[j..i-1] 的元素和
            if (preSum[i] - preSum[j] == k)
                res++;

    return res;
}
```

这个解法的时间复杂度为O(N^2)，空间复杂度为O(N)，并不是最优的解法。不过在通过这个解法理解了前缀和数组的工作原理后，可以使用一些巧妙的办法把时间复杂度进一步降低。

注意上述解法中的双层循环中的内层循环所做的事可以概括为：计算有多少个`j`能够使得`preSum[i]`和`preSum[j]`的差为`k`，也即`preSum[j]=preSum[i]-k`，当找到一个`j`满足就把结果加一。

优化的思路就是：直接记录下有几个`preSum[j]`和`preSum[i]-k`相等，直接更新结果，从而避免内层循环。我们可以使用Map，在记录前缀和的同时记录该前缀和出现的次数。

```java
int subarraySum(int[] nums, int k) {
    int n = nums.length;
    // map：前缀和 -> 该前缀和出现的次数
    HashMap<Integer, Integer> 
        preSum = new HashMap<>();
    // base case
    preSum.put(0, 1);

    int res = 0, sum0_i = 0;
    for (int i = 0; i < n; i++) {
        sum0_i += nums[i];
        // 这是我们想找的前缀和 nums[0..j]
        int sum0_j = sum0_i - k;
        // 如果前面有这个前缀和，则直接更新答案
        if (preSum.containsKey(sum0_j))
            res += preSum.get(sum0_j);
        // 把前缀和 nums[0..i] 加入并记录出现次数
        preSum.put(sum0_i, 
            preSum.getOrDefault(sum0_i, 0) + 1);
    }
    return res;
}
```

这样，就把时间复杂度降到了O(N)，是最优解法。

### 差分

前缀和主要适用的场景是原始数组不会被修改的情况下，频繁查询某个区间的累加和。而查分的主要**适用场景是频繁对原始数组的某个区间的元素进行增减**。

举例：有一个数组`nums`，要求先给区间`nums[2...6]`全部加上1，再给区间`nums[3...9]`全部减3，再给区间`nums[0...4]`全部加2，再给区间……一番操作结束后，问：最后`nums`数组的元素各是多少？

常规的思路很简单，对每一次的增减要求都使用一个`for`循环依次对区间内的元素进行增减。这种思路的时间复杂度为O(N)，但是因为对`nums`的修改会经常发生，所以效率会十分低下。

这里我们可以使用差分数组的技巧，类似前缀和技巧构造的前缀和数组，我们可以对`nums`数组构造一个`diff`差分数组，`diff[i]`就是`nums[i]`和`nums[i-1]`之差。

```java
int[] diff = new int[nums.length];
// 构造差分数组
diff[0] = nums[0];
for (int i = 1; i < nums.length; i++) {
    diff[i] = nums[i] - nums[i - 1];
}
```

**通过这个`diff`差分数组是可以反推出原始数组`nums`的**，代码逻辑如下：

```java
int[] res = new int[diff.length];
// 根据差分数组构造结果数组
res[0] = diff[0];
for (int i = 1; i < diff.length; i++) {
    res[i] = res[i - 1] + diff[i];
}
```

这很好理解，因为对于第一个元素，`nums[0]=diff[0]`，后续的元素都满足`diff[i]=num[i]-num[i-1]`，则`nums[i]=nums[i-1]+diff[i]`。

**这样构造差分数组`diff`，就可以快速进行区间增减的操作**。如果想对区间`nums[i...j]`的元素全部加上3，那么只需让`diff[i]+=3`，然后再让`diff[j+1]-=3`即可。

原理很简单，对区间`[i...j]`的元素全部加上3，显然地（假设数组长度为n+1）：

1. 对原数组`nums`：`nums[0...i-1]`和`nums[j+1...n]`的值没有发生任何变化。
2. 对差分数组`diff`：`diff[0...i-1]`和`diff[j+2...n]`的值没有发生任何变化，因为`diff[i]`涉及`nums[i]`，`diff[j]`和`diff[j+1]`都涉及`nums[j]`。
3. 考虑`diff[i]`：因为`diff[i]=nums[i]-nums[i-1]`，而`nums[i-1]`不变、`nums[i]`增加3，所以`diff[i]+=3`.
4. 考虑`diff[j]`和`diff[j+1]`：因为`diff[j]=nums[j]-nums[j-1]`、`diff[j+1]=nums[j+1]-nums[j]`，而`nums[j+1]`不变、`nums[j]`和`nums[j-1]`都增加3，所以`diff[j]`不变，`diff[j+1]`-=3。
5. 考虑`diff[i+1...j-1]`：因为参与计算的所有的元素都同时增加了3，所以`diff[i+1...j-1]`不变。

反推的过程：`diff[i] += 3`意味着给`nums[i...n]`所有的元素都加了 3，然后`diff[j+1] -= 3`又意味着对于`nums[j+1...n]`所有元素再减 3，那综合起来，是不是就是对`nums[i..j]`中的所有元素都加 3 了。

现在我们把差分数组抽象成一个类，包含`increment`和`result`方法：

```java
// 差分数组工具类
class Difference {
    // 差分数组
    private int[] diff;

    /* 输入一个初始数组，区间操作将在这个数组上进行 */
    public Difference(int[] nums) {
        assert nums.length > 0; //assert断言关键字，当后面的条件为false时会抛出异常
        diff = new int[nums.length];
        // 根据初始数组构造差分数组
        diff[0] = nums[0];
        for (int i = 1; i < nums.length; i++) {
            diff[i] = nums[i] - nums[i - 1];
        }
    }

    /* 给闭区间 [i,j] 增加 val（可以是负数）*/
    public void increment(int i, int j, int val) {
        diff[i] += val;
        if (j + 1 < diff.length) {
            diff[j + 1] -= val;
        }
    }

    /* 返回结果数组 */
    public int[] result() {
        int[] res = new int[diff.length];
        // 根据差分数组构造结果数组
        res[0] = diff[0];
        for (int i = 1; i < diff.length; i++) {
            res[i] = res[i - 1] + diff[i];
        }
        return res;
    }
}
```

最后，差分数组和前缀和数组都是比较常见且巧妙的算法技巧，分别适用不同的常见，而且是会者不难，难者不会。

[1094. 拼车 - 力扣（LeetCode）](https://leetcode.cn/problems/car-pooling/description/)

题目：

>车上最初有 `capacity` 个空座位。车 **只能** 向一个方向行驶（也就是说，**不允许掉头或改变方向**）
>
>给定整数 `capacity` 和一个数组 `trips` ,  `trip[i] = [numPassengersi, fromi, toi]` 表示第 `i` 次旅行有 `numPassengersi` 乘客，接他们和放他们的位置分别是 `fromi` 和 `toi` 。这些位置是从汽车的初始位置向东的公里数。
>
>当且仅当你可以在所有给定的行程中接送所有乘客时，返回 `true`，否则请返回 `false`。
>
>提示：`0 <= fromi < toi <= 1000`

示例：

> 输入：trips=[[2,1,5]，[3,3,7]]，capacity =4
>
> 输出：false
>
> 
>
> 输入：trips=[[2,1,5]，[3,3,7]]，capacity=5
>
> 输出：true

可以联想到**差分的技巧——对某区间元素的增减**：`trips[i]`代表着一组区间操作，乘客的上车和下车就相当于数组的区间加减；只要结果数组中的所有元素都小于`capacity`，就说明可以在所有给定的行程中接送所有乘客。

因为`0 <= fromi < toi <= 1000`，所以差分数组的长度为1001（下标从0到1000）。

为了简化计算，对于`trips[i]=[numPassengersi, fromi, toi]`表示的从`fromi`上车（`nums[fromi...toi]`全加`numPassengersi`）、在`toi`下车（`nums[toi]`减`numPassengers`），其实可以直接看做：`numPassengers`个乘客仅在`fromi`到`toi-1`的乘车区间内在车上，所以只需`nums[fromi...toi-1]`全加`numPassengersi`即可。

```java
boolean carPooling(int[][] trips, int capacity) {
    // 最多有 1000 个车站
    int[] nums = new int[1001];
    // 构造差分解法
    Difference df = new Difference(nums);

    for (int[] trip : trips) {
        // 乘客数量
        int val = trip[0];
        // 第 trip[1] 站乘客上车
        int i = trip[1];
        // 第 trip[2] 站乘客已经下车，
        // 即乘客在车上的区间是 [trip[1], trip[2] - 1]
        int j = trip[2] - 1;
        // 进行区间操作
        df.increment(i, j, val);
    }

    int[] res = df.result();

    // 客车自始至终都不应该超载
    for (int i = 0; i < res.length; i++) {
        if (capacity < res[i]) {
            return false;
        }
    }
    return true;
}
```



### 字典树（Trie树、单词查找树、前缀树）

Trie树又叫字典树、前缀树、单词查找树，是一种二叉树衍生出来的高级数据结构，主要的应用场景是**处理字符串前缀相关的操作**。

Trie树本质上就是一棵多叉树。

```
/* 基本的多叉树节点 */
class TreeNode {
   	[datatype] val;
    TreeNode[] children;
}
```

其中的`children`数组中存储的是指向子节点的指针。

此时如果对数据结构的基础知识掌握很好，应该可以想到如何使用这样的多叉树去构造所谓的“字典树”、“前缀树”。

**Trie树的根节点一般不具有实际存储字符的意义，仅仅是作为一个指针，便于我们从根节点出发搜索这棵树。**

在构造的时候，我们应该首先明确以下几点：

+ 这棵多叉树的节点值的定义是什么，或者说节点值应该存放什么？
+ 怎么在多叉树中体现“字符串前缀”信息，也即对于一个字符串`s`，我们如何从根结点出发查找树中是否含有该字符串呢？
+ 在搜索这棵多叉树时，我们应该怎么选择路径（下一个访问的节点）？

其实以上问题可以合并为一个问题：我们应该用节点存储字符，还是用“枝”存储字符。

#### 使用节点存储字符

显然，这种方式就是用节点值`val`存储字符串中的某个单词。

```
class TrieNode{
	char val;
	TrieNode[] children;
}
```

假设现在有字典：[[hello],[world],[work]]，按照上面的数据结构构造了一棵字典树`Trie`，显然对于`hello`、`world`、`work`的搜索过程是：从根节点出发，只要搜索到当前节点的路径组成的单词为所求即可。这样构造的`Trie`存在一个问题，当搜索的单词为某个单词的前缀时，即使该单词不在字典中，也会被当做存在于字典，如`wo`。

显然，这种方式存在不足，即如何判断从根结点到当前节点组成的单词是合法的（存在于字典中）。一种最为直接的方式就是扩充节点的数据域。

```
class TrieNode{
	char val;
	int count; //用单词出现的次数判断单词合法，<=0:非法，>0:合法
	TrieNode[] children;
}
```

另一种方式就是节点值`val`不用来存储字符，使用指针域数组`children[]`下标`i`表示字符。

#### 使用指针域数组下标存储字符

假设字符串只能由26个小写的英文字母`[a-z]`组成，那么我们可以定义字典树的节点结构为：

```
class TrieNode{
	[datatype] val;
	TrieNode[26] children;
}
```

**`TrieNode`中`children`数组的索引是有意义的，代表一个字符**。比如将索引`0-25`按顺序代表英文小写字母`a-z`。

比如`children[4] != null`，说明这里存储了一个字符`e`，因为`e`在英文小写字母里排第5个。

通过这种方式，我们就将字符信息存储在“树枝”里。那么空出来的节点值就可以存储一些特定含义的信息，比如存储字符串在字典中出现的次数。



## 一些构想

### 超级源点

在最短路问题中，如果我们要求**多个源点出发**的最短路时，一般我们都会**建立一个「超级源点」连向所有的源点**，用「超级源点」到终点的最短路等价多个源点到终点的最短路。
