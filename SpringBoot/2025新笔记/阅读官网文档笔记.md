# 阅读官网文档

## 随记

> Spring Boot dependencies use the `org.springframework.boot` group id. Typically, your Maven POM file inherits from the `spring-boot-starter-parent` project and declares dependencies to one or more [starters](https://docs.spring.io/spring-boot/reference/using/build-systems.html#using.build-systems.starters). 

总结：使用Maven管理Spring Boot项目时，项目的POM文件可以直接继承自`spring-boot-starter-parent`工程，再在`pom.xml`文件中声明其他需要的“starter”依赖。

继承`spring-boot-starter-parent`工程，需要在`pom.xml`中编辑`<parent>`元素：

```xml
  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>xx.xx.xx</version>
    <relativePath/> <!-- lookup parent from repository -->
  </parent>
```



> Before we begin, open a terminal and run the following commands to ensure that you have a valid version of Java installed

> If you want to use Maven, ensure that you have Maven installed

> If you want to use Gradle, ensure that you have Gradle installed

总结：使用Spring Boot需要安装合适的JDK以及项目管理工具（Maven，也可以选择Gradle）。

> Most Spring Boot applications use the `spring-boot-starter-parent` in the `parent` section of the POM. The `spring-boot-starter-parent` is a special starter that provides useful Maven defaults. It also provides a [`dependency-management`](https://docs.spring.io/spring-boot/reference/using/build-systems.html#using.build-systems.dependency-management) section so that you can omit `version` tags for “blessed” dependencies.

总结：在`pom.xml`文件的`<parent>`元素中使用`spring-boot-starter-parent`可以提供POM中Maven依赖的默认有用值。

> The `mvn dependency:tree` command prints a tree representation of your project dependencies. You can see that `spring-boot-starter-parent` provides no dependencies by itself. To add the necessary dependencies, edit your `pom.xml` and add the `spring-boot-starter-web` dependency immediately below the `parent` section

>If you run `mvn dependency:tree` again, you see that there are now a number of additional dependencies, including the Tomcat web server and Spring Boot itself.

总结：`spring-boot-starter-parent`本身不提供任何依赖项，项目需要的依赖项是由各个`starter`引入的。`spring-boot-starter-web`依赖包含有`spring-boot-starter`依赖提供的Spring Boot容器自身。

> The [`@RestController`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/web/bind/annotation/RestController.html) and [`@RequestMapping`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/web/bind/annotation/RequestMapping.html) annotations are Spring MVC annotations (they are not specific to Spring Boot).

总结：`Controller`和`Mapping`相关注解不是Spring Boot提供的，而是Spring MVC的注解。

>The second class-level annotation is [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html). This annotation is known as a *meta-annotation*, it combines [`@SpringBootConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringBootConfiguration.html), [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) and [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html).

总结：`@SpringBootApplication`注解是`@SpringBootConfiguration`、`@EnableAutoConfiguration`、`@ComponentScan`三个注解组合的元注解，具有三个注解的功能。

> [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) tells Spring Boot to “guess” how you want to configure Spring, based on the jar dependencies that you have added. Since `spring-boot-starter-web` added Tomcat and Spring MVC, the auto-configuration assumes that you are developing a web application and sets up Spring accordingly.

总结：`@EnableAutoConfiguration`注解是Spring Boot实现“自动配置”的关键注解，它使得Spring Boot框架根据添加的依赖包自动地在Spring容器中配置，而不用通过编写xml文件配置。`spring-boot-starter-web`依赖提供有`Tomcat`和`Spring MVC`等依赖。

> Auto-configuration is designed to work well with starters, but the two concepts are not directly tied. You are free to pick and choose jar dependencies outside of the starters. Spring Boot still does its best to auto-configure your application.

总结：Spring Boot的自动配置特点的最佳作用对象是`starter`，但是当使用其他的jar依赖时，Spring Boot依然尽力去自动配置应用。

> Each release of Spring Boot provides a curated list of dependencies that it supports. In practice, you do not need to provide a version for any of these dependencies in your build configuration, as Spring Boot manages that for you. When you upgrade Spring Boot itself, these dependencies are upgraded as well in a consistent way.

> Each release of Spring Boot is associated with a base version of the Spring Framework. We **highly** recommend that you do not specify its version.

> You can still specify a version and override Spring Boot’s recommendations if you need to do so.

总结：每个Spring Boot的发布版本都自己管理了Spring Boot支持的依赖，所以在项目的依赖管理中可以不需要指定依赖的版本。当然如果一定要指定版本也是可以的，只是不推荐。

> Starters are a set of convenient dependency descriptors that you can include in your application. You get a one-stop shop for all the Spring and related technologies that you need without having to hunt through sample code and copy-paste loads of dependency descriptors. 

总结：`starter`提供了应用开发过程中所需的Spring和相关技术的依赖（可以简单理解为库）。

>All **official** starters follow a similar naming pattern; `spring-boot-starter-*`, where `*` is a particular type of application. This naming structure is intended to help when you need to find a starter. The Maven integration in many IDEs lets you search dependencies by name. For example, with the appropriate Eclipse or Spring Tools plugin installed, you can press `ctrl-space` in the POM editor and type “spring-boot-starter” for a complete list.
>
>As explained in the [Creating Your Own Starter](https://docs.spring.io/spring-boot/reference/features/developing-auto-configuration.html#features.developing-auto-configuration.custom-starter) section, third party starters should not start with `spring-boot`, as it is reserved for official Spring Boot artifacts. Rather, a third-party starter typically starts with the name of the project. For example, a third-party starter project called `thirdpartyproject` would typically be named `thirdpartyproject-spring-boot-starter`.

总结：Spring Boot官方的`starter`命名以`spring-boot-starter-`开头，后接应用类型；第三方或自己的`starter`建议以`-spring-boot-starter`结尾，前接第三方项目名。

>When a class does not include a `package` declaration, it is considered to be in the “default package”. The use of the “default package” is generally discouraged and should be avoided. It can cause particular problems for Spring Boot applications that use the [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html), [`@ConfigurationPropertiesScan`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/context/properties/ConfigurationPropertiesScan.html), [`@EntityScan`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/domain/EntityScan.html), or [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) annotations, since every class from every jar is read.

> We recommend that you follow Java’s recommended package naming conventions and use a reversed domain name (for example, `com.example.project`).

> We generally recommend that you locate your main application class in a root package above other classes. The [`@SpringBootApplication` annotation](https://docs.spring.io/spring-boot/reference/using/using-the-springbootapplication-annotation.html) is often placed on your main class, and it implicitly defines a base “search package” for certain items. For example, if you are writing a JPA application, the package of the [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) annotated class is used to search for [`@Entity`](https://jakarta.ee/specifications/persistence/3.1/apidocs/jakarta.persistence/jakarta/persistence/Entity.html) items. Using a root package also allows component scan to apply only on your project.

>The following listing shows a typical layout:

```none
com
 +- example
     +- myapplication
         +- MyApplication.java
         |
         +- customer
         |   +- Customer.java
         |   +- CustomerController.java
         |   +- CustomerService.java
         |   +- CustomerRepository.java
         |
         +- order
             +- Order.java
             +- OrderController.java
             +- OrderService.java
             +- OrderRepository.java
```

总结：项目中的编写的代码文件建议使用`package`语句声明所属包，不要使用默认包（`default package`）。因为默认包中的类（广义，包括类、接口等）使用`@ComponentScan`、`@ConfigurationPropertiesScan`、`@EntityScan`、`@SpringBootApplication`注解时，会扫描每一个`jar`（依赖）中的所有类，增加应用启动开销，存在冲突风险。

使用`@SpringBootApplication`注解主应用类时，使用`package`语句将该类放置到根包（`root package`）中，它隐式的定义了项目扫描的基本包，Spring Boot项目启动时扫描类自根包往下的包扫描。根包命名建议使用反域名的命名，如`com.example.project`。

主应用类放在根包，项目中其他的类则根据需要放在根包下的各层包中。

> Spring Boot favors Java-based configuration. Although it is possible to use [`SpringApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringApplication.html) with XML sources, we generally recommend that your primary source be a single [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) class. Usually the class that defines the `main` method is a good candidate as the primary [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html).

> You need not put all your [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) into a single class. The [`@Import`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Import.html) annotation can be used to import additional configuration classes. Alternatively, you can use [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html) to automatically pick up all Spring components, including [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) classes.

> If you absolutely must use XML based configuration, we recommend that you still start with a [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) class. You can then use an [`@ImportResource`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ImportResource.html) annotation to load XML configuration files.

总结：Spring Boot推荐使用基于Java的配置，并且在项目中最好只在`main`方法所在的“主类”上使用`@Configuration`注解。若要导入其他的配置，可以使用`@Import`注解导入其他的配置类；或者配置类使用`@Configuration`注解，但通过在“主类”上使用`@ComponentScan`注解去自动获取Spring组件，包括配置类。

如果一定要使用基于`XML`的配置方式，推荐在`@Configuration`类使用`@ImportResource`注解加载XML配置文件。

> Spring Boot auto-configuration attempts to automatically configure your Spring application based on the jar dependencies that you have added. For example, if `HSQLDB` is on your classpath, and you have not manually configured any database connection beans, then Spring Boot auto-configures an in-memory database.

总结：Spring Boot会尝试自动为添加的依赖进行配置。

> You need to opt-in to auto-configuration by adding the [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) or [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) annotations to one of your [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) classes.

> You should only ever add one [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) or [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) annotation. We generally recommend that you add one or the other to your primary [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) class only.

总结：Spring Boot的自动配置通过在某个配置类上使用`@EnableAutoConfiguration`注解或`@SpringBootApplication`注解实现，并且只能添加一个`@EnableAutoConfiguration`或`@SpringBootApplication`注解，推荐将注解用在主配置类（“主类”）上。

> Auto-configuration is non-invasive. At any point, you can start to define your own configuration to replace specific parts of the auto-configuration. For example, if you add your own [`DataSource`](https://docs.oracle.com/en/java/javase/17/docs/api/java.sql/javax/sql/DataSource.html) bean, the default embedded database support backs away.

总结：自动配置是非侵入式的（即并不是和Spring Boot强耦合的），可以自己定义配置去替换自动配置中的特定部分。

> If you need to find out what auto-configuration is currently being applied, and why, start your application with the `--debug` switch. Doing so enables debug logs for a selection of core loggers and logs a conditions report to the console.

总结：如果要了解当前正在应用的自动配置是什么以及原因，可以在启动应用时使用`--debug`参数，查看控制台的日志。

> If you find that specific auto-configuration classes that you do not want are being applied, you can use the exclude attribute of [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) to disable them, as shown in the following example:
>
> ```java
> import org.springframework.boot.autoconfigure.SpringBootApplication;
> import org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration;
> 
> @SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })
> public class MyApplication {
> 
> }
> ```

> If the class is not on the classpath, you can use the `excludeName` attribute of the annotation and specify the fully qualified name instead. If you prefer to use [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) rather than [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html), `exclude` and `excludeName` are also available. Finally, you can also control the list of auto-configuration classes to exclude by using the `spring.autoconfigure.exclude` property.

总结：如果我们要禁用某些特定的自动配置类，可以使用`@SpringBootApplication`注解或`@EnableAutoConfiguration`注解的`exclude`和`excludeName`属性指明禁用的自动配置类，前者是`.class`文件，后者是类名，同时注意当配置类不在类路径（classpath）上时，需要给出类的完全限定名。除此之外，还可以在应用程序的配置文件中通过配置属性`spring.autoconfigure.exclude`来禁用自动配置类。

> Auto-configuration packages are the packages that various auto-configured features look in by default when scanning for things such as entities and Spring Data repositories. The [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html) annotation (either directly or through its presence on [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html)) determines the default auto-configuration package. Additional packages can be configured using the [`@AutoConfigurationPackage`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/AutoConfigurationPackage.html) annotation.

总结：自动配置包是自动配置功能在扫描像实体、Spring Data数据库等内容时默认查找的包。`@EnableAutoConfiguration`注解决定了默认的自动配置包，使用`@AutoConfigurationPackage`注解可以配置其他的包。

>You are free to use any of the standard Spring Framework techniques to define your beans and their injected dependencies. We generally recommend using constructor injection to wire up dependencies and [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html) to find beans.

总结：Spring Boot支持Spring框架提供的各种Spring Bean定义以及依赖注入技术，但是推荐使用**构造器（构造函数）**的方式进行依赖注入，并使用`@ComponentScan`注解扫描Spring Bean。

> If you structure your code as suggested above (locating your application class in a top package), you can add [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html) without any arguments or use the [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) annotation which implicitly includes it. All of your application components ([`@Component`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/stereotype/Component.html), [`@Service`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/stereotype/Service.html), [`@Repository`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/stereotype/Repository.html), [`@Controller`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/stereotype/Controller.html), and others) are automatically registered as Spring Beans.

总结：如果我们将应用程序类放在根包（root package）或称顶包（top package），那么在主应用程序上使用`@ComponentScan`注解不用额外添加参数，就可以自动获取到组件（`@Component`、`@Service`、`@Repository`、`@Controller`等注解标记的类）并登记为Spring Bean。

> If a bean has more than one constructor, you will need to mark the one you want Spring to use with [`@Autowired`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/beans/factory/annotation/Autowired.html)

总结：使用构造器实现依赖注入时，如果有多个构造函数（构造器）时，需要在希望Spring框架使用的构造函数上使用`@Autowired`注解标记。

> Many Spring Boot developers like their apps to use auto-configuration, component scan and be able to define extra configuration on their "application class". A single [`@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html) annotation can be used to enable those three features, that is:
>
> + [`@EnableAutoConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/autoconfigure/EnableAutoConfiguration.html): enable [Spring Boot’s auto-configuration mechanism](https://docs.spring.io/spring-boot/reference/using/auto-configuration.html)
> + [`@ComponentScan`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/ComponentScan.html): enable [`@Component`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/stereotype/Component.html) scan on the package where the application is located (see [the best practices](https://docs.spring.io/spring-boot/reference/using/structuring-your-code.html))
> + [`@SpringBootConfiguration`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringBootConfiguration.html): enable registration of extra beans in the context or the import of additional configuration classes. An alternative to Spring’s standard [`@Configuration`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/Configuration.html) that aids [configuration detection](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html#testing.spring-boot-applications.detecting-configuration) in your integration tests.

总结：Spring Boot提供的自动配置、组件扫描、自定义配置的功能由`@SpringBootApplication`注解启用，`SpringBootApplication`注解又由`@EnableAutoConfiguration`、`@ComponentScan`、`@SpringBootConfiguration`三个注解组合。

`@EnableAutoConfiguration`注解启用自动配置机制。

`@ComponentScan`注解启用组件（`@Component`）扫描，且以使用注解的类所在包向下扫描。

`@SpringBootConfiguration`注解启用在上下文中注册bean或导入额外的配置类，是Spring 标准注解`@Configuration`的替换，可有助于在集成测试中进行配置检测。

> None of these features are mandatory and you may choose to replace this single annotation by any of the features that it enables. For instance, you may not want to use component scan or configuration properties scan in your application:

总结：`@SpringBootApplication`注解所含有的三个注解功能不是必须的，可以只单独使用其中的某几个启用对应的功能即可。

> [`SpringApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringApplication.html) allows an application to be initialized lazily. When lazy initialization is enabled, beans are created as they are needed rather than during application startup. As a result, enabling lazy initialization can reduce the time that it takes your application to start. In a web application, enabling lazy initialization will result in many web-related beans not being initialized until an HTTP request is received.

总结：`SpringApplication`允许应用程序延迟初始化。延迟初始化可以加快应用启动时间，它是通过将Bean的创建（初始化）延迟到需要Bean的时候，而不是应用启动时。对于Web应用，延迟初始化使得与Web相关的bean直到接收到HTTP请求时才初始化。

> A downside of lazy initialization is that it can delay the discovery of a problem with the application. If a misconfigured bean is initialized lazily, a failure will no longer occur during startup and the problem will only become apparent when the bean is initialized. Care must also be taken to ensure that the JVM has sufficient memory to accommodate all of the application’s beans and not just those that are initialized during startup. For these reasons, lazy initialization is not enabled by default and it is recommended that fine-tuning of the JVM’s heap size is done before enabling lazy initialization.

总结：延迟初始化可能导致的问题，错误配置的bean初始化发现的时间被推迟，原本服务启动就可以发现的bean初始化问题出现在服务启动后。还有一个问题是因为bean不在服务启动时初始化，而是bean需要时初始化，可能导致服务运行时JVM没有足够的内存容纳应用程序的bean，所以默认不启动延迟初始化，建议在启动延迟初始化前对JVM的堆大小做一些调整。

Alternatively, it can be enabled using the `spring.main.lazy-initialization` property as shown in the following example

总结：启动延迟初始化的方法很多，一个简单的方法就是设置属性`spring.main.lazy-initialization=true`。

> If you want to disable lazy initialization for certain beans while using lazy initialization for the rest of the application, you can explicitly set their lazy attribute to false using the `@Lazy(false)` annotation.

总结：若要在使用延迟初始化的同时保持一些bean不使用延迟初始化，可以对这些bean使用注解`@Lazy(false)`。

> A [`SpringApplication`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringApplication.html) attempts to create the right type of [`ApplicationContext`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/ApplicationContext.html) on your behalf. The algorithm used to determine a [`WebApplicationType`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/WebApplicationType.html) is the following:
>
> + If Spring MVC is present, an [`AnnotationConfigServletWebServerApplicationContext`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/web/servlet/context/AnnotationConfigServletWebServerApplicationContext.html) is used
> + If Spring MVC is not present and Spring WebFlux is present, an [`AnnotationConfigReactiveWebServerApplicationContext`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/web/reactive/context/AnnotationConfigReactiveWebServerApplicationContext.html) is used
> + Otherwise, [`AnnotationConfigApplicationContext`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/AnnotationConfigApplicationContext.html) is used

总结：Spring Boot中`SpringApplication`总是尝试自动地创建正确的`ApplicationContext`类型。它利用这样的算法规则确定一个`WebApplicationType`（Web应用类型）：第一优先级是存在Spring MVC依赖，就使用`AnnotationConfigServletWebServerApplicationContext`；第二优先级是不存在Spring MVC，但存在Spring WebFlux依赖，就使用`AnnotationConfigReactiveWebServerApplicationContext`；除此之外，使用`AnnotationConfigApplicationContext`。

总结：当有多种类型的WebApplicationType时，可以通过调用`setWebApplicationType()`方法去覆盖某些默认的类型。

> Sources are considered in the following order:
>
> 1. Default properties (specified by setting [`SpringApplication.setDefaultProperties(Map)`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/SpringApplication.html#setDefaultProperties(java.util.Map))).

This is too late to configure certain properties such as `logging.*` and `spring.main.*` which are read before refresh begins.
>
> 3. Config data (such as `application.properties` files).
>
> 4. A [`RandomValuePropertySource`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/env/RandomValuePropertySource.html) that has properties only in `random.*`.
>
> 5. OS environment variables.
> 6. Java System properties (`System.getProperties()`).
>
> 7. JNDI attributes from `java:comp/env`.
>
> 8. [`ServletContext`](https://jakarta.ee/specifications/servlet/6.0/apidocs/jakarta.servlet/jakarta/servlet/ServletContext.html) init parameters.
>
> 9. [`ServletConfig`](https://jakarta.ee/specifications/servlet/6.0/apidocs/jakarta.servlet/jakarta/servlet/ServletConfig.html) init parameters.
>
> 10. Properties from `SPRING_APPLICATION_JSON` (inline JSON embedded in an environment variable or system property).
>
> 11. Command line arguments. 
> 12. `properties` attribute on your tests. Available on [`@SpringBootTest`](https://docs.spring.io/spring-boot/3.5.0/api/java/org/springframework/boot/test/context/SpringBootTest.html) and the [test annotations for testing a particular slice of your application](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html#testing.spring-boot-applications.autoconfigured-tests).
> 13. [`@DynamicPropertySource`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/test/context/DynamicPropertySource.html) annotations in your tests.
> 14. [`@TestPropertySource`](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/test/context/TestPropertySource.html) annotations on your tests.
> 15. [Devtools global settings properties](https://docs.spring.io/spring-boot/reference/using/devtools.html#using.devtools.globalsettings) in the `$HOME/.config/spring-boot` directory when devtools is active.

总结：Spring Boot使用一个特定的顺序来指明应用加载配置的过程，后面加载的配置可以覆盖前者加载的相同配置值：

1. 使用`SpringApplication.setDefaultProperties(Map)`设置的默认配置
2. `@Configuration`配置类上的`@PropertySource`注解配置源
3. 配置数据文件，比如常用的`application.properties`文件
4. 只在`random.*`中具属性的`RandomValuePropertySource`
5. 操作系统环境变量
6. Java系统属性
7. 来自`java:comp:env`的JNDI属性
8. `ServlertContext`的初始化参数
9. `ServletConfig`的初始化参数
10. `SPRING_APPLICATION_JSON`的属性
11. 命令行参数
12. 测试类中的`properties`属性，只在`@SpringBootTest`注解及测试有关注解中可用
13. 测试类中的`DynamicPropertySource`注解，也只在测试阶段可用
14. 测试类中的`TestPropertySource`注解，也只在测试阶段可用
15. 在Spring Boot的开发工具（devTool）处于激活（可用）时，`$HOME/.config/spring-boot`目录中的开发工具全局配置属性设置

> 2. [Profile-specific application properties](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.files.profile-specific) packaged inside your jar (`application-{profile}.properties` and YAML variants).
> 3. [Application properties](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.files) outside of your packaged jar (`application.properties` and YAML variants).

>As well as `application` property files, Spring Boot will also attempt to load profile-specific files using the naming convention `application-{profile}`. 总结：Spring Boot尽力尝试去加载使用命名规定的`application-{profile}`的特定配置文件作为应用程序在某个环境中工作的配置文件。通过`spring.profiles.active`属性来指定一个或多个配置文件生效，多个配置文件生效时会发生配置属性值的覆盖，覆盖的策略为`last-wins`，即最后指定的配置文件覆盖前面的配置。如`spring.profiles.active`属性指定`prod,live`，则`application-prod.properties`文件中的配置属性值会被`application-live.properties`文件中的配置覆盖。

总结：Spring可以通过在`@Component`、`@COnfiguration`、`@ConfigurationProperties`注解使用处标记`@Profile`去限制何时加载配置。如果`@ConfigurationProperties`bean不是被自动扫描而是被`@EnableConfigurationProperties`注册的，那么`@Profile`注解需要被特定在有`@EnableCofigurationProperties`注解的`@Configuration`类。

总结：使用`spring.profiles.active`环境属性去激活（生效）特定的配置文件。如果没有配置文件被激活，则使用默认的配置文件，且可以通过`spring.profiles.default`环境属性去调整。`spring.profiles.active`和`spring.profiles.default`只能被用在没有特定配置文件的文档中。

> Spring Boot uses [Commons Logging](https://commons.apache.org/logging) for all internal logging but leaves the underlying log implementation open. In each case, loggers are pre-configured to use console output with optional file output also available.

总结：Spring Boot使用`Commons Logging`作为内部的日志，当也保留对底层的日志实现开放，默认配置提供有`Java Util Logging `、`Log4j2`、`Logback`等日志实现工具，并且日志记录预先配置使用控制台输出，但也可选择文件输出日志。

总结：如果使用`starter`，默认使用`Logback`记录日志，合适的`Logback`路由确保使用`Java Util Logging`、`Commons Logging`、`Log4j2`、`SLF4J`的依赖库能正常工作。通常不需要改变日志依赖，因为Spring Boot的默认状态就能很好地工作。

> When you deploy your application to a servlet container or application server, logging performed with the Java Util Logging API is not routed into your application’s logs. 总结：应用部署到一个servlet容器或应用服务器时，不需要担心使用`Java Util Logging`的API的其他已部署程序的日志会路由到应用的日志中，即防止容器或已部署到容器的其他应用程序执行的日志记录显示在应用程序的日志中。

> The default log output from Spring Boot resembles the following example:

>+ Log Level: `ERROR`, `WARN`, `INFO`, `DEBUG`, or `TRACE`.
>+ Process ID.

>+ Correlation ID: If tracing is enabled (not shown in the sample above)
>+ Logger name: This is usually the source class name (often abbreviated).
>+ The log message.

总结：Spring Boot默认的日志输出有以下内容：

> By default, Spring Boot logs only to the console and does not write log files. If you want to write log files in addition to the console output, you need to set a `logging.file.name` or `logging.file.path` property (for example, in your `application.properties`). If both properties are set, `logging.file.path` is ignored and only `logging.file.name` is used.
>
> The following table shows how the `logging.*` properties can be used together:
>
> | `logging.file.name`                   | `logging.file.path`                          | Description                                                  |
> | :------------------------------------ | :------------------------------------------- | :----------------------------------------------------------- |
> | *(none)*                              | *(none)*                                     | Console only logging.                                        |
> | Specific file (for example, `my.log`) | *(none)*                                     | Writes to the location specified by `logging.file.name`. The location can be absolute or relative to the current directory. |
> | *(none)*                              | Specific directory (for example, `/var/log`) | Writes `spring.log` to the directory specified by `logging.file.path`. The directory can be absolute or relative to the current directory. |
> | Specific file                         | Specific directory                           | Writes to the location specified by `logging.file.name` and ignores `logging.file.path`. The location can be absolute or relative to the current directory. |

总结：希望Spring Boot将日志记录写到文件中而不是控制台，需要再配置文件（如`application.properties`）中设置`logging.file.name`或`logging.file.path`属性指明日志文件或日志路径，两个属性同时设置，则使用`logging.file.name`属性值，忽略`logging.file.path`属性值。

设置`logging.file.name`和`logging.file.path`属性时，都可以使用绝对路径或相对路径（对于当前目录），但前者指定特定的文件，如`my.log`，后者在指定的目录下生成`spring.log`文件记录日志。
